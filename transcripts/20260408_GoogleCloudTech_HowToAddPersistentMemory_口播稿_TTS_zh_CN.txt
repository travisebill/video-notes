Google Cloud Tech 推出 Agent memory 系列教学影片， 这是系列第二集， 介绍怎么帮 AI agent 加 persistent memory。 影片用七分多钟说明两件事， 把 chat 本身变成 persistent， 以及加一个 user profile store。 Session 在 in-memory 模式下 app restart 就全没了， 所以第一个改进是切换到 database session service， 把每则 user message、 agent reply、 state change 都存到磁碟， app restart 后用同一个 session ID 就能回复完整对话历史继续对话； ADK 提供三种 session service， 包括 in-memory（快但短暂）、 database（自己管资料库， 会话跨重启存活）、 Vertex AI（Google Cloud 管理， 下一集 deep dive 记忆库）。 第二个改进是 user profile store， persistent sessions 解决同一个对话跨重启的问题， 但新对话新 session ID 就没 transcript 可读， 所以加一个小的结构化资料表， 一个 user ID 一个 preference key， 存像 dietary、 favorite、 transport mode 等重要事实； agent 透过两个 tools 存取， Recall User Preference 读所有存过的偏好， Save User Preference 插入新 key 或更新现有 key， 两个 tools 都从 context 拿到当前 user ID 所以读写都对应到正确的人。 Agent 指令是四步， 先 recall 然后 personalize 跟 plan、 present 跟 learn（问有没有新偏好要存）、 最后 save。 Demo 显示 vegetarian user 存偏好、 app restart、 新对话 recall 出 vegetarian 立即 personalize， 证明 persistent sessions 跟 user profile store 两个机制互补， 前者延续同一个对话， 后者跨不同对话跟不同日期个人化。 整支影片的核心讯息是， 要让 agent 不只 session 内记得还要跨 session 个人化， ADK 提供三种 session service 切换跟 user profile store tools 这套组合， 下一集会建 memory bank 存整个对话跟媒体， 再用语意搜寻在新对话捞回有用事实。
