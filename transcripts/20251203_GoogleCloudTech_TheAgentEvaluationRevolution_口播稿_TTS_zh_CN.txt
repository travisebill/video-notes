Google Cloud Tech 推出 AI agent 评估系列教学影片， 这是系列第一集， 介绍为什么 agent 评估跟传统软体测试完全不同——传统软体是确定性的， 相同输入永远相同输出， unit test 和 integration test 都很有效， 但 AI agent 是机率性的且自主的， 会计划、 调适、 使用工具， 每次执行可能走不同路径， 可能选错工具、 遗失重要 context、 或 timeout， 所以单纯检查最终答案等于某个值会错过中间发生的一切， 必须观察整个旅程包括计划形成、 工具使用、 资讯传递、 使用者是否真的得到想要的结果。 Agent 评估是系统层级测试， 测的是整个 stack 包括 LM brain、 prompt、 外部工具、 记忆系统、 orchestration 逻辑， 问的是整个系统是否可靠地达成目标， 检查项目包括最终输出（task success rate、 stepwise progress、 output quality 包括 coherence/accuracy/clarity/safety 涵盖 bias 和 prompt injection 防御）、 planning and reasoning（如何拆解复杂目标、 如何合理正当化每步）、 tool use（能否有效使用工具、 选对工具、 传对参数、 处理输出、 避免冗余成本）、 memory and context（记得重点、 准确检索过去资讯、 处理长距离 context 和冲突、 对 RAG 而言要检索 precision 和 recall）， 量测每一层有助于 debug； multi-agent 评估实际案例：两个 customer service agent——A 负责前线客户支援和转交， B 负责退款和换货； 用户说买了 smart vision 一周没开机要退款或换货， A 确认订单但不能退款转交给 B 处理； 如果只单独测 A 会以为 0% 成功（因为 A 不退款）， 但 A 成功因为它的任务是转交资讯不是退款； 如果 A 传错 order ID 给 B 但 B 成功退款， 整个系统其实失败因为 A 传错资料， 所以 multi-agent 评估要知道整个 network 是否达成目标、 共用 context 是否安全传递、 整个系统是否在成本和延迟上保持效率。 整支影片的核心讯息是：agent 评估是系统层级的四步流程（outcome / reasoning / tools / memory）， 不是单纯的 model 测试， 下一集会介绍 test pyramid 和用 ADK 设计与执行实际测试。
