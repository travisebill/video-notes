本集 AI Hero 技能库由 Matt Pocock 主讲，聚焦于一个他在 LLM 编码时代长期反对、却日益盛行的反模式 — spec-driven development。Matt 在影片开头直接点明核心张力：需要制定一个计划，对吧？计划模式，规范驱动开发。需要投入所有精力来制定这个极其详细的规范⋯⋯而在这种冲动之下，他们忘了自己其实可以写程式。这项观察呼应敏捷开发时代的原型设计传统，但 Matt 更进一步指出，随著 LLM 编码成本大幅下降，「生产原型、快速生产一次性尖头产品从未如此便宜，也从未如此有效。」

第一个张力是设计讨论的保真度分级。Matt 将设计问题分为三层：简单的基本框架问题（例如 modal 应有取消/确认按钮）透过纯讨论即可解决；中等保真度的问题（例如模态框开启时如何展示资料）需要更高层级的探讨；而真正复杂的事物外观 + 在特定情境的行为方式，则只能在半工作程式码中测试。从经济学角度，这呼应了 Ryan Singer 在《Shape Up》中提出的「拉力 vs 推力」框架 — 当讨论的精确度降低，答案的实用性也降低，但 token 成本也降低；保真度越高则反之。

第二个张力是 `/prototype` 与 `/wayfinder` 的工具整合。Matt 展示 Wayfinder 的票种设计：预设是 grill（与 agent 对话厘清范围），但当「它应该看起来怎么样」「它应该如何表现」成为关键问题时，切换到 prototype 票 — 制作廉价、粗糙、具体的工件来回答问题。从工具哲学角度，这体现了「context-dependent fidelity」原则：同一个 skill 系统内，根据问题性质动态切换讨论模式，是 LLM 时代设计工具的核心演化方向。

第三个张力是实战 demo 揭露的反直觉发现。Matt 为自己的 TLDraw 图表绘制 app 加搜寻栏，因资料模型复杂（图表 + 时间快照），启动 prototype 生成 A/B/C 三个版本。每次迭代使用约 10 万 token，但产出的是「保留所有设计决策 + 给反馈」的高保真资产，而非随意丢弃的草稿。最终 D 版本合并了 A 的搜寻框 + C 的布局，并与即时路由整合 — 让 prototype 成为「程式码实际运作方式的真实写照」，而非纸上谈兵。

结尾转向 prototype 的非 UI 应用。Matt 反对「原型只跟前端有关」的刻板印象，展示一个处理状态机的小型互动终端应用 — 纯逻辑 prototype。从软体工程史角度，这呼应了 1970 年代 Smalltalk 环境中「先建构可运作的最小实例，再扩展为完整系统」的探索式编程传统。Matt 最后引用 Ryan Singer 的《Shape Up》作为思想根源：「从讨论和规范到可用于生产的程式码，这之间的差距非常大。然而，如果你有一个可用的原型，将其转化为量产产品就相当简单了。」

这支影片最鲜明的口号是：原型不是浪费时间，而是用最便宜的程式码，回答最难的设计问题 — 在 LLM 时代，当程式码成本趋近于零，设计讨论的保真度天花板，便决定了最终产品的品质上限。
