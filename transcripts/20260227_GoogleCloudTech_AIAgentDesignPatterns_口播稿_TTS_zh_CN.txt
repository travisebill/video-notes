Google Cloud Tech 推出 Agents pattern 系列教学影片， 这是系列第一集， 介绍 AI agent design patterns——影片用八分多钟展示三个基本 pattern：single agent、 sequential agent、 parallel agent。 Single agent 是最基础的 pattern， 用一个 agent 加一组 tools 处理任务， 例如规划旅游用 Google search tool 查天气、 交通、 行程； 好处是实作简单灵活， 坏处是对复杂 workflow 控制力不够， 因为 AI 是 non-deterministic 不能保证每次都完美遵循多步逻辑， 当任务变复杂时 single agent 会需要越来越大的 prompt 来定义所有逻辑， 行为会变得不可靠。 Sequential agent 是多 agent pattern 之一， 适合高度结构化可重复的任务， 运作方式像组装线：subagent A 的 output 直接成为 subagent B 的 input， 例如规划旅游拆成两个专门 agent——一个找餐厅、 一个找交通， sequential agent 确保永远先跑找餐厅再跑找交通； 好处是高度控制跟可靠比 single agent 可预测， 坏处是刚性预定义结构难以调适动态情境； subagent 之间透过 shared session state（共享白板/短期记忆）沟通， 前一个 agent 写结果下一个 agent 读。 Parallel agent 当任务不需要按顺序时就能用， 例如规划完整旅游要同时找好博物馆、 好音乐厅、 好餐厅， parallel agent 让多个专门 agent 同时跑（museum finder、 concert finder、 restaurant finder 并行搜寻）， 比 sequential 快很多； 通常会跟 sequential agent 组合， 先 parallel 搜寻再 sequential aggregator agent 整合成完整旅游计划， 好处是大幅降低 latency， 坏处是初始成本较高（同时跑多个 agent）且需要 gather/synthesize 步骤整合结果。 整支影片的核心讯息是：选对 pattern 取决于任务特性——straightforward multi-step 用 single agent、 fixed order 结构化任务用 sequential agent、 independent tasks 降低 latency 用 parallel agent； 三个 pattern 组合就能建构强大 workflow， 下一集会介绍更进阶的 pattern 包括 loop + critique 自我修正、 coordinator 动态 routing、 agent as tool。
