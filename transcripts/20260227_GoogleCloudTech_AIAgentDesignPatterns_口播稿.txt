Google Cloud Tech 推出 Agents pattern 系列教學影片，這是系列第一集，介紹 AI agent design patterns，影片用八分多鐘展示三個基本 pattern：single agent、sequential agent、parallel agent。Single agent 是最基礎的 pattern，用一個 agent 加一組 tools 處理任務，例如規劃旅遊用 Google search tool 查天氣、交通、行程；好處是實作簡單靈活，壞處是對複雜 workflow 控制力不夠，因為 AI 是 non-deterministic 不能保證每次都完美遵循多步邏輯，當任務變複雜時 single agent 會需要越來越大的 prompt 來定義所有邏輯，行為會變得不可靠。Sequential agent 是多 agent pattern 之一，適合高度結構化可重複的任務，運作方式像組裝線：subagent A 的 output 直接成為 subagent B 的 input，例如規劃旅遊拆成兩個專門 agent，一個找餐廳、一個找交通，sequential agent 確保永遠先跑找餐廳再跑找交通；好處是高度控制跟可靠比 single agent 可預測，壞處是剛性預定義結構難以調適動態情境；subagent 之間透過 shared session state（共享白板/短期記憶）溝通，前一個 agent 寫結果下一個 agent 讀。Parallel agent 當任務不需要按順序時就能用，例如規劃完整旅遊要同時找好博物館、好音樂廳、好餐廳，parallel agent 讓多個專門 agent 同時跑（museum finder、concert finder、restaurant finder 並行搜尋），比 sequential 快很多；通常會跟 sequential agent 組合，先 parallel 搜尋再 sequential aggregator agent 整合成完整旅遊計畫，好處是大幅降低 latency，壞處是初始成本較高（同時跑多個 agent）且需要 gather/synthesize 步驟整合結果。整支影片的核心訊息是：選對 pattern 取決於任務特性，straightforward multi-step 用 single agent、fixed order 結構化任務用 sequential agent、independent tasks 降低 latency 用 parallel agent；三個 pattern 組合就能建構強大 workflow，下一集會介紹更進階的 pattern 包括 loop + critique 自我修正、coordinator 動態 routing、agent as tool。
