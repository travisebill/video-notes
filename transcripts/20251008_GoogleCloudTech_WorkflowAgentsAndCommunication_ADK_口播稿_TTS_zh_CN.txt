Google Cloud Tech 推出 Google Agent Development Kit 系列教学影片， 这是第二集也是完结篇。 影片用将近五分钟介绍 ADK 的两大进阶主题：workflow agents 控制 agent 执行顺序， 以及 communication mechanisms 让 agent 之间传递资料。 第一部分介绍三种 workflow agent。 Sequential agent 像组装线， 每个 sub-agent 依固定顺序执行、 传递结果， 适合有顺序相依的任务； parallel agent 像 manager 同时派工给三个员工， 适合独立任务例如多 API 并行呼叫； loop agent 重复执行直到条件满足或达到最大迭代次数， 适合除错与迭代改进。 第二部分介绍三种 communication mechanism。 Shared session state 像共享白板， 一个 agent 写结果、 下一个 agent 读取， 是 ADK 最基本的通讯方式； LLM-driven delegation 由 coordinator agent 像 CEO 看完需求后决定派给哪个 sub-agent， 适合需要动态判断的场景； explicit invocation - agent as a tool 把另一个 agent 包成 function-style tool， 由 parent agent 决定何时呼叫， 适合跨越 hierarchy 边界的工具化呼叫。 影片最后对比 sub-agent 与 agent-as-tool 的差异。 Sub-agent 是组织图的一部分， 永远被 parent agent 管理； agent-as-tool 像外部顾问， 用才叫、 不在 core hierarchy。 这个区别是开发者设计多 agent 协作的关键选择点。 整支影片的核心讯息是：multi-agent 系统不只需要 hierarchy 结构， 还需要 workflow agents 控制执行顺序， 加上 communication mechanisms 让 agent 之间传递资料。 ADK 透过这三加三的框架， 让开发者可以建构结构化又灵活的多 agent 协作系统。
