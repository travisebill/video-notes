Google Cloud Tech 推出 Google Agent Development Kit 系列教学影片， 这是第二集完结篇。 影片用将近五分钟介绍 ADK 两大进阶主题：workflow agents 控制 agent 执行顺序， 以及 communication mechanisms 让 agent 之间传递资料。 第一部分介绍三种 workflow agent：Sequential agent 像组装线， 每个 sub-agent 依固定顺序执行、 传递结果， 适合有顺序相依的任务； Parallel agent 像 manager 同时派工给三个员工， 适合独立任务例如多 API 并行呼叫； Loop agent 重复执行直到条件满足或达到最大迭代次数， 适合除错与迭代改进。 第二部分介绍三种 communication mechanism：Shared session state 像共享白板， 一个 agent 写结果、 下一个 agent 读取； LLM-driven delegation 由 coordinator agent 像 CEO 看完需求后决定派给哪个 sub-agent； Explicit invocation - agent as a tool 把另一个 agent 包成 function-style tool， 由 parent agent 决定何时呼叫。 影片最后对比 sub-agent 与 agent-as-tool 的差异， Sub-agent 是组织图的一部分永远被 parent agent 管理， Agent-as-tool 像外部顾问用才叫不在 core hierarchy。 整支影片核心讯息：multi-agent 系统需要 hierarchy 结构、 workflow agents、 communication mechanisms 三大支柱， ADK 透过这三加三的框架让开发者建构结构化又灵活的多 agent 协作系统。
