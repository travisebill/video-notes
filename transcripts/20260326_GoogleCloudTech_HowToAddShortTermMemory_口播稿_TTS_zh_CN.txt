Google Cloud Tech 推出 Agent memory 系列教学影片， 这是系列第一集， 介绍怎么帮 AI agent 加 short-term memory。 影片用六分多钟说明 session 概念， 以及 event 和 state 两个关键元件。 Session 是一次连续对话像手机上一个 chat thread， ADK Web UI 预设用 in-memory session service； 问题是如果每次 turn 都开新 session， agent 会像每次都第一次见面一样完全忘记之前对话内容， demo 显示 turn 1 规划 Lisbon 两天旅游 day 1、 turn 2 问 day 2 但 agent 已经忘了 city 和 day 1 计划。 解法是用同一个 session 跨多个 turn， 这样 agent 能回头看完整对话历史调整 plan。 Session 里有两个关键元件：event 像逐字稿记录每则 user message 和 agent reply 包括 media input， 提供 agent context 读早期讯息； state 像结构化小便利贴存快速存取的值如餐厅名字、 确认号码， state 存在是因为不想让 model 重读 15 则讯息只为找一个值。 Agent 之间透过 session state 沟通的范例：agent A 找餐厅输出餐厅名字 map 到 destination 这个 key， agent B 自动收到 destination 当变数， 这样多 agent 协作不用每次 scrape 整个 transcript。 重要原则是不要在 tool code 直接修改 session object， 因为改动不会被记录到 event log 和 persistent service， 应该用 ADK 给的 context 或 callback， 写到 context. state ADK 会记录变更到 event 就能存到未来的 database 和 long-term memory。 短语记忆的特性是快速但暂时， 下一集会加 persistence 让 agent 能跨 app restart 还记得 user。
