Google Cloud Tech 推出 Agent memory 系列教學影片，這是系列第一集，介紹怎麼幫 AI agent 加 short-term memory。影片用六分多鐘說明 session 概念，以及 event 和 state 兩個關鍵元件。Session 是一次連續對話像手機上一個 chat thread，ADK Web UI 預設用 in-memory session service；問題是如果每次 turn 都開新 session，agent 會像每次都第一次見面一樣完全忘記之前對話內容，demo 顯示 turn 1 規劃 Lisbon 兩天旅遊 day 1、turn 2 問 day 2 但 agent 已經忘了 city 和 day 1 計畫。解法是用同一個 session 跨多個 turn，這樣 agent 能回頭看完整對話歷史調整 plan。Session 裡有兩個關鍵元件：event 像逐字稿記錄每則 user message 和 agent reply 包括 media input，提供 agent context 讀早期訊息；state 像結構化小便利貼存快速存取的值如餐廳名字、確認號碼，state 存在是因為不想讓 model 重讀 15 則訊息只為找一個值。Agent 之間透過 session state 溝通的範例：agent A 找餐廳輸出餐廳名字 map 到 destination 這個 key，agent B 自動收到 destination 當變數，這樣多 agent 協作不用每次 scrape 整個 transcript。重要原則是不要在 tool code 直接修改 session object，因為改動不會被記錄到 event log 和 persistent service，應該用 ADK 給的 context 或 callback，寫到 context.state ADK 會記錄變更到 event 就能存到未來的 database 和 long-term memory。短語記憶的特性是快速但暫時，下一集會加 persistence 讓 agent 能跨 app restart 還記得 user。
