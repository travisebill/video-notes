各位聽眾，現在為各位介紹的是 Matt Pocock 在 2026 年 8 月 5 日發佈的 Claude Skills v1.2.0 版本更新影片，整支影片長度為 11 分 37 秒。影片以 Skills, skills, skills 的招呼開場，把這個目前已是 GitHub 史上第 24 名、24K stars 的工程技能 repo 正式宣告進入成熟期，接著依序交代三大主軸的變更。講者開場就講了這麼一句：「The skills repo is now, I think, the 24th most starred repo of all time on GitHub, up to 24K stars.」，用雙二十四這個巧合把成熟期的到來說得相當到位。

影片的第一個重點，是這個 repo 的生態擴張。講者先介紹了新上線的官方文件站 aihero.dev/skills，這份文件由他的團隊整理，左側面板是所有技能的完整參考手冊，主視覺則是一條從 grill、with-docs、spec、tickets 一直到 implement 與 code-review 的開發流程圖，文件中還連結到講者長期維護的 AI 編碼字典，讓使用者可以同時學技能與學概念。講者特別說，這份文件以前是他個人要花全職工時寫的東西，這次有團隊協助之後品質明顯提升，他也笑說自己回到老本行。文件站右側還嵌入了一份個人 wiki 提煉出的常見問題清單，列出所有過去使用者最常問的問題與講者自己的回答。

接下來講者說明這個 skills 已經進入 Claude Code 官方 plugin marketplace，使用者在 Claude Code 內輸入 plugin 指令、搜尋 Matt Pocock 後即可一鍵安裝成唯讀 bundle，所有後續更新會自動 pull 下來。為了照顧 Codex 使用者，每個 skill 還多了一個 OpenAI.YAML sidecar 檔，讓 Codex UI 也能開箱即用，並透過這個 sidecar 帶上 allow_implicit invocation false 的語意，補齊過去在 Claude Code 與 Pi 上才支援的隱藏式 context 注入機制。這個看似微小的 sidecar 設計其實解決了一個過去很多使用者沒意識到的相容性問題，因為某些題目雖然是 model invocable、某些是 user invocable，而這個分界本來只能在 Claude Code 與 Pi 的執行環境下才有意義，現在透過 sidecar 就變成 portable 的標準設定。

影片的第二個重點，是三個核心技能的改寫，回應了講者自己在使用上遇到的真實痛點。第一個是全新技能 wait-what，這個技能是為了治 Opus 5 在對話時滿嘴 LLM 慣用語與過度冗長的毛病。講者一開場就說 Opus 真的太能講廢話了，他試過 output styles 與 AGENTS.md 加註解都沒用，最後發現唯一有效的是寫一個專門的技能。講者特別點出這個 skill 的兩個關鍵：第一個關鍵是引用 ASD-STE100 簡化技術英文規範，這是一份航空業使用的寫作標準，規定用簡短祈使句、控制句子長度、避免被動句；第二個關鍵是把 Agent 的詞彙拉回到 context.md 裡的 ubiquitous language 上，這個詞彙表其實是 grill-with-docs 跑出來的，所以兩個 skill 之間形成一個閉環。講者用一句話把這個 skill 的哲學講得相當精準：「The real cure for verbosity is not to tell it to use simple language... is to tell it to use your language, the stuff that you have come up to in grill with docs.」這個觀察暗示，想修某個特定症狀最好的方法是寫一個專門的 skill，而不是去改全域 prompt。

第二個被改寫的是 grill-me，舊版流程是一次一題、慢慢問，到了 session 後半段都是瑣碎的確認題，變成不停回答 yes, that sounds good 的地獄；新版把題目結構看成有向圖，安排成 round 1、round 2 的 frontier 推進模式，使用者一次可以答完一輪所有可達的題目。這個改寫牽涉到一個關鍵的設計決策，原本題目因為一次只問一個所以不會有相依性問題，但現在多題並答就要考慮到第三題可能要等第一題先答完才有意義。講者的解法是把題目看成圖形，開場有一個關鍵題必須先打開，那題答完之後才會打開下一輪新題目，整個 skill 不斷把題目沿著 frontier 往前推。介面上講者用 emoji 標題搭配建議答案，主要針對聽寫輸入做最佳化，讓整個 grilled session 的速度明顯加快。

第三個改寫的是 writing-for-agents，講者坦言原本的 writing-great-skills 早就被他拿來寫 AGENTS.md、CLAUDE.md 與所有 agent 配置檔，所以新版本直接拓寬範圍，並把抽 AGENTS.md 出來變成 skill 的去前段灌入策略做成模板，同時宣告這個 skill 是 model invocable 的，讓 Agent 在自動修改 agents.md 時會自動拉進來使用。講者最後補一句，他發現這個 skill 變成他每次寫任何 agent 配置時都會叫出來用的工具，使用頻率高到驚人。

影片的第三個重點，是兩個全新技能處理過去比較不受注意但其實很煩的場景。第一個是 wizard，講者最近要大量架設 AWS 與各類基礎設施，發現讓 Agent 自己用 computer-use 去點 console 既不放心又覺得有點 icky，所以他讓 Agent 改為產出一個 deterministic 的互動式 bash 向導，每個步驟只把只有人類能做的部分交給使用者，剩下的寫檔與推到 GitHub secrets 都自動完成，整個流程不送任何資料到 Anthropic。講者現場 demo 一個遷移到遠端機器的範例，只見他說 ready to start，向導就引導他到正確的頁面登入、貼 API key，貼完值會自動寫入正確檔案與 GitHub secrets。講者笑說這個技能把原本痛苦得要命的服務架設變得 weirdly joyful，他自己每天都在用。第二個是 questionnaire，它把 grill-me 對話中的問題序列抽成 Markdown 文件，放進 Google Doc 給不會用 AI 的利害關係人評論，例如講者自己蓋花園辦公室時需要老婆一起決策，這時就把問題文件化等兩人一起填完再倒回 Agent。講者特別說明這個技能其實是一個 patch，他希望未來 Agent 能直接在 Slack 與人類協作時，這個技能就可以功成身退。講者對這個未來想像得很具體，他覺得最好的團隊配置是讓 Agent 進駐 Slack，人類在 channel 對話時自動 tag Agent，Agent 看見 tag 就 pile-in 開始實作。

影片的最後，講者談到他對整個 AI coding 領域的個人判斷。他認為這個領域自去年 12 月以來變化已經不大，技術正在沉澱下來，他原話是這樣講的：「My personal opinion about AI coding is that it's kind of settling down a little bit... I now feel confident enough that I can put out a self-paced course that hopefully won't change too much even as things develop.」基於這個觀察，他預告一個全年可看、價格更親民的 AI coding 速成課程即將上線，目前開放 waitlist 報名，預計在幾週後發佈。講者強調，他之所以敢推出自學式課程，是因為他相信能給使用者一個穩固的基礎讓他們真的開始 ship，而這個課程的定位也呼應了 Skills v1.2 所代表的穩定版本節奏。整支影片的 meta 訊號很清楚，版本號推進速度放慢是為了把品質拉高，使用者現在可以安心把這套技能帶進生產線。

以上就是這支影片的重點摘要，感謝各位聆聽。
