Google Cloud Tech 推出 AI agent 評估系列教學影片，這是系列第一集，介紹為什麼 agent 評估跟傳統軟體測試完全不同——傳統軟體是確定性的，相同輸入永遠相同輸出，unit test 和 integration test 都很有效，但 AI agent 是機率性的且自主的，會計畫、調適、使用工具，每次執行可能走不同路徑，可能選錯工具、遺失重要 context、或 timeout，所以單純檢查最終答案等於某個值會錯過中間發生的一切，必須觀察整個旅程包括計畫形成、工具使用、資訊傳遞、使用者是否真的得到想要的結果。Agent 評估是系統層級測試，測的是整個 stack 包括 LM brain、prompt、外部工具、記憶系統、orchestration 邏輯，問的是整個系統是否可靠地達成目標，檢查項目包括最終輸出（task success rate、stepwise progress、output quality 包括 coherence/accuracy/clarity/safety 涵蓋 bias 和 prompt injection 防禦）、planning and reasoning（如何拆解複雜目標、如何合理正當化每步）、tool use（能否有效使用工具、選對工具、傳對參數、處理輸出、避免冗余成本）、memory and context（記得重點、準確檢索過去資訊、處理長距離 context 和衝突、對 RAG 而言要檢索 precision 和 recall），量測每一層有助於 debug；multi-agent 評估實際案例：兩個 customer service agent——A 負責前線客戶支援和轉交，B 負責退款和換貨；用戶說買了 smart vision 一週沒開機要退款或換貨，A 確認訂單但不能退款轉交給 B 處理；如果只單獨測 A 會以為 0% 成功（因為 A 不退款），但 A 成功因為它的任務是轉交資訊不是退款；如果 A 傳錯 order ID 給 B 但 B 成功退款，整個系統其實失敗因為 A 傳錯資料，所以 multi-agent 評估要知道整個 network 是否達成目標、共用 context 是否安全傳遞、整個系統是否在成本和延遲上保持效率。整支影片的核心訊息是：agent 評估是系統層級的四步流程（outcome / reasoning / tools / memory），不是單純的 model 測試，下一集會介紹 test pyramid 和用 ADK 設計與執行實際測試。
