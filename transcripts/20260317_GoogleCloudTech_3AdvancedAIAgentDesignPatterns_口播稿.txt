Google Cloud Tech 推出 Agentic pattern 系列教學影片，這是系列第二集，介紹三個進階 agent design patterns，包括 loop review critique、coordinator router、agent as tool。第一個是 loop review critique pattern，用 generator agent 加上 critique agent 形成迴圈，generator 產生初步結果、critique 檢查是否符合條件，不符合就把結果和反饋送回 generator 修改，重複直到通過或達到最大迭代次數（避免無限迴圈），例如規劃旅遊時要求飯店和活動場地交通時間在 30 分鐘內就是非妥協條件；好處是確保輸出符合特定品質標準和約束條件，壞處是多輪迭代增加 latency 和成本，設計 exit condition 本身也增加複雜度。第二個是 coordinator router pattern，top-level coordinator 像聰明的 project manager，分析用戶需求後把大任務拆成子任務委派給專門 sub-agents，例如規劃完整體驗時 coordinator 委派給 food/transport 序向 agent、nearby places 並行 agent、trip calls agent，sub-agents 各自執行再回傳結果；用 LLM agent 實作 sub-agents 就能動態選擇；好處是極度靈活能解決複雜問題，壞處是因為多層 routing 增加 latency 和成本，加上多層結構設計和除錯更複雜。第三個是 agent as tool pattern，跟 coordinator 表面相似但關鍵差異在控制權和狀態管理，coordinator 把任務委派後 sub-agent 拿走完整控制權自己解決，agent as tool 則是 primary agent 把 sub-agents 當無狀態工具呼叫，sub-agent 執行一個函式回傳結果，主要 agent 保留完整控制權管理整體狀態，例如 coordinator 像 manager 把專案交給員工、agent as tool 像工匠拿起特定工具做完一步再換下一步。整支影片的核心訊息是，選對 pattern 取決於需求特性，simple prototype 用 single agent，reliable structured workflow 用 sequential 或 parallel agent，要符合特定條件用 loop，要動態靈活 routing 解複雜問題用 coordinator 或 agent as tool，每個 design 在 control、flexibility、cost、complexity 之間都有 trade-off。
