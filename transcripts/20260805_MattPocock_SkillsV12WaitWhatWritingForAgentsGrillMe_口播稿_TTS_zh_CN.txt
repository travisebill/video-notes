各位听众，现在为各位介绍的是 Matt Pocock 在 2026 年 8 月 5 日发布的 Claude Skills v1.2.0 版本更新影片，整支影片长度为 11 分 37 秒。影片以 Skills, skills, skills 的招呼开场，把这个目前已是 GitHub 史上第 24 名、24K stars 的工程技能 repo 正式宣告进入成熟期，接著依序交代三大主轴的变更。讲者开场就讲了这么一句：「The skills repo is now, I think, the 24th most starred repo of all time on GitHub, up to 24K stars.」，用双二十四这个巧合把成熟期的到来说得相当到位。

影片的第一个重点，是这个 repo 的生态扩张。讲者先介绍了新上线的官方文件站 aihero.dev/skills，这份文件由他的团队整理，左侧面板是所有技能的完整参考手册，主视觉则是一条从 grill、with-docs、spec、tickets 一直到 implement 与 code-review 的开发流程图，文件中还连结到讲者长期维护的 AI 编码字典，让使用者可以同时学技能与学概念。讲者特别说，这份文件以前是他个人要花全职工时写的东西，这次有团队协助之后品质明显提升，他也笑说自己回到老本行。文件站右侧还嵌入了一份个人 wiki 提炼出的常见问题清单，列出所有过去使用者最常问的问题与讲者自己的回答。

接下来讲者说明这个 skills 已经进入 Claude Code 官方 plugin marketplace，使用者在 Claude Code 内输入 plugin 指令、搜寻 Matt Pocock 后即可一键安装成唯读 bundle，所有后续更新会自动 pull 下来。为了照顾 Codex 使用者，每个 skill 还多了一个 OpenAI.YAML sidecar 档，让 Codex UI 也能开箱即用，并透过这个 sidecar 带上 allow_implicit invocation false 的语意，补齐过去在 Claude Code 与 Pi 上才支援的隐藏式 context 注入机制。这个看似微小的 sidecar 设计其实解决了一个过去很多使用者没意识到的相容性问题，因为某些题目虽然是 model invocable、某些是 user invocable，而这个分界本来只能在 Claude Code 与 Pi 的执行环境下才有意义，现在透过 sidecar 就变成 portable 的标准设定。

影片的第二个重点，是三个核心技能的改写，回应了讲者自己在使用上遇到的真实痛点。第一个是全新技能 wait-what，这个技能是为了治 Opus 5 在对话时满嘴 LLM 惯用语与过度冗长的毛病。讲者一开场就说 Opus 真的太能讲废话了，他试过 output styles 与 AGENTS.md 加注解都没用，最后发现唯一有效的是写一个专门的技能。讲者特别点出这个 skill 的两个关键：第一个关键是引用 ASD-STE100 简化技术英文规范，这是一份航空业使用的写作标准，规定用简短祈使句、控制句子长度、避免被动句；第二个关键是把 Agent 的词汇拉回到 context.md 里的 ubiquitous language 上，这个词汇表其实是 grill-with-docs 跑出来的，所以两个 skill 之间形成一个闭环。讲者用一句话把这个 skill 的哲学讲得相当精准：「The real cure for verbosity is not to tell it to use simple language... is to tell it to use your language, the stuff that you have come up to in grill with docs.」这个观察暗示，想修某个特定症状最好的方法是写一个专门的 skill，而不是去改全域 prompt。

第二个被改写的是 grill-me，旧版流程是一次一题、慢慢问，到了 session 后半段都是琐碎的确认题，变成不停回答 yes, that sounds good 的地狱；新版把题目结构看成有向图，安排成 round 1、round 2 的 frontier 推进模式，使用者一次可以答完一轮所有可达的题目。这个改写牵涉到一个关键的设计决策，原本题目因为一次只问一个所以不会有相依性问题，但现在多题并答就要考虑到第三题可能要等第一题先答完才有意义。讲者的解法是把题目看成图形，开场有一个关键题必须先打开，那题答完之后才会打开下一轮新题目，整个 skill 不断把题目沿著 frontier 往前推。介面上讲者用 emoji 标题搭配建议答案，主要针对听写输入做最佳化，让整个 grilled session 的速度明显加快。

第三个改写的是 writing-for-agents，讲者坦言原本的 writing-great-skills 早就被他拿来写 AGENTS.md、CLAUDE.md 与所有 agent 配置档，所以新版本直接拓宽范围，并把抽 AGENTS.md 出来变成 skill 的去前段灌入策略做成模板，同时宣告这个 skill 是 model invocable 的，让 Agent 在自动修改 agents.md 时会自动拉进来使用。讲者最后补一句，他发现这个 skill 变成他每次写任何 agent 配置时都会叫出来用的工具，使用频率高到惊人。

影片的第三个重点，是两个全新技能处理过去比较不受注意但其实很烦的场景。第一个是 wizard，讲者最近要大量架设 AWS 与各类基础设施，发现让 Agent 自己用 computer-use 去点 console 既不放心又觉得有点 icky，所以他让 Agent 改为产出一个 deterministic 的互动式 bash 向导，每个步骤只把只有人类能做的部分交给使用者，剩下的写档与推到 GitHub secrets 都自动完成，整个流程不送任何资料到 Anthropic。讲者现场 demo 一个迁移到远端机器的范例，只见他说 ready to start，向导就引导他到正确的页面登入、贴 API key，贴完值会自动写入正确档案与 GitHub secrets。讲者笑说这个技能把原本痛苦得要命的服务架设变得 weirdly joyful，他自己每天都在用。第二个是 questionnaire，它把 grill-me 对话中的问题序列抽成 Markdown 文件，放进 Google Doc 给不会用 AI 的利害关系人评论，例如讲者自己盖花园办公室时需要老婆一起决策，这时就把问题文件化等两人一起填完再倒回 Agent。讲者特别说明这个技能其实是一个 patch，他希望未来 Agent 能直接在 Slack 与人类协作时，这个技能就可以功成身退。讲者对这个未来想像得很具体，他觉得最好的团队配置是让 Agent 进驻 Slack，人类在 channel 对话时自动 tag Agent，Agent 看见 tag 就 pile-in 开始实作。

影片的最后，讲者谈到他对整个 AI coding 领域的个人判断。他认为这个领域自去年 12 月以来变化已经不大，技术正在沉淀下来，他原话是这样讲的：「My personal opinion about AI coding is that it's kind of settling down a little bit... I now feel confident enough that I can put out a self-paced course that hopefully won't change too much even as things develop.」基于这个观察，他预告一个全年可看、价格更亲民的 AI coding 速成课程即将上线，目前开放 waitlist 报名，预计在几周后发布。讲者强调，他之所以敢推出自学式课程，是因为他相信能给使用者一个稳固的基础让他们真的开始 ship，而这个课程的定位也呼应了 Skills v1.2 所代表的稳定版本节奏。整支影片的 meta 讯号很清楚，版本号推进速度放慢是为了把品质拉高，使用者现在可以安心把这套技能带进生产线。

以上就是这支影片的重点摘要，感谢各位聆听。
