Google Cloud Tech 推出 Agent memory 系列教學影片，這是系列第二集，介紹怎麼幫 AI agent 加 persistent memory。影片用七分多鐘說明兩件事，把 chat 本身變成 persistent，以及加一個 user profile store。Session 在 in-memory 模式下 app restart 就全沒了，所以第一個改進是切換到 database session service，把每則 user message、agent reply、state change 都存到磁碟，app restart 後用同一個 session ID 就能回復完整對話歷史繼續對話；ADK 提供三種 session service，包括 in-memory（快但短暫）、database（自己管資料庫，會話跨重啟存活）、Vertex AI（Google Cloud 管理，下一集 deep dive 記憶庫）。第二個改進是 user profile store，persistent sessions 解決同一個對話跨重啟的問題，但新對話新 session ID 就沒 transcript 可讀，所以加一個小的結構化資料表，一個 user ID 一個 preference key，存像 dietary、favorite、transport mode 等重要事實；agent 透過兩個 tools 存取，Recall User Preference 讀所有存過的偏好，Save User Preference 插入新 key 或更新現有 key，兩個 tools 都從 context 拿到當前 user ID 所以讀寫都對應到正確的人。Agent 指令是四步，先 recall 然後 personalize 跟 plan、present 跟 learn（問有沒有新偏好要存）、最後 save。Demo 顯示 vegetarian user 存偏好、app restart、新對話 recall 出 vegetarian 立即 personalize，證明 persistent sessions 跟 user profile store 兩個機制互補，前者延續同一個對話，後者跨不同對話跟不同日期個人化。整支影片的核心訊息是，要讓 agent 不只 session 內記得還要跨 session 個人化，ADK 提供三種 session service 切換跟 user profile store tools 這套組合，下一集會建 memory bank 存整個對話跟媒體，再用語意搜尋在新對話撈回有用事實。
