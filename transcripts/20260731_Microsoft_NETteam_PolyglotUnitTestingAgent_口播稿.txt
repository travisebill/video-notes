2026 年 7 月 31 日，微軟 .NET 團隊在 DevBlogs 發布 open-source 工具 code-testing-generator。這個 agent 屬於 dotnet-test plugin，存放在 GitHub 的 dotnet/skills repository，主打 polyglot 單元測試生成。

這篇文章的核心問題很直白。當開發者對 coding agent 丟一句「幫我寫單元測試」，這行 prompt 留了五個空白：哪段程式碼要測？用哪個測試框架？測試放哪個資料夾？build 系統怎麼找到這些測試？測試要驗證什麼？

code-testing-generator 把整個流程拆成四階段。第一階段是學習 repository：偵測語言、測試框架、找到正確的 build 與 test 指令，避免新測試在本地能跑、在 CI 卻被漏掉的窘境。第二階段是選擇工作量：小任務用 Direct 路徑，中任務做一次 Single pass 規劃，大任務進入 Iterative 循環。第三階段是規劃並寫測試，從簡單程式碼開始，逐步處理依賴較多的部分，並嚴格遵守 repository 的慣例。第四階段是檢查測試價值，做 mutation testing，驗證 assertion 是否夠強，確認所有需求場景都有對應測試，最後執行完整 build 與測試套件。

微軟用內部 152 個任務做基準測試。專門 agent 通過率 92.1%，stock GitHub Copilot 通過率 78.9%，整體失敗減少 63%。差異最大的是模糊提示：89 個任務中，專門 agent 通過 79 個，stock Copilot 只通過 59 個，失敗從 30 降到 10，減少 67%。詳細提示雙方平手，都是 61 個。整體 20 個淨增益全部來自模糊提示，呼應 agent 的設計目標：執行 prompt 中缺少的研究工作。

跨模型比較涵蓋 Claude Opus 4.8、GPT-5.5、Claude Haiku 4.5。專門 agent 在 .NET 45 個任務上全面領先，失敗減少 45% 到 80%。跨語言涵蓋 .NET、Python、TypeScript、JavaScript、Java、Go、Ruby、Rust、Swift、Kotlin、PowerShell、C++ 等 12 種。Python 任務從 6 個通過提升到 13 個，Go 任務從 10 個通過提升到全部 15 個通過。

第二個基準測試 SWE Atlas 更難，會注入 bugs 驗證測試的 catch 能力。44 個任務中，專門 agent 通過 16 個，stock Copilot 通過 12 個。微軟強調這些結果代表 reliability 提升，不是 coverage 提升。最終平均覆蓋率相差不到 0.5 個百分點，但專門 agent 速度快 5.5%，生成的測試數量略少 2.3%，靠的是可靠性而非數量。

文章最後是試用指引。Copilot CLI 用 plugin marketplace add 與 plugin install 兩個指令即可安裝，VS Code 透過 plugin support 支援，Visual Studio 仍在開發中。微軟總結，良好的測試需要被規劃、被建置、被執行、被檢查，這就是團隊正在打造的信任循環。
