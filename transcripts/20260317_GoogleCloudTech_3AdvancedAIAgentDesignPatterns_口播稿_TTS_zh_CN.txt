Google Cloud Tech 推出 Agentic pattern 系列教学影片， 这是系列第二集， 介绍三个进阶 agent design patterns， 包括 loop review critique、 coordinator router、 agent as tool。 第一个是 loop review critique pattern， 用 generator agent 加上 critique agent 形成回圈， generator 产生初步结果、 critique 检查是否符合条件， 不符合就把结果和反馈送回 generator 修改， 重复直到通过或达到最大迭代次数（避免无限回圈）， 例如规划旅游时要求饭店和活动场地交通时间在 30 分钟内就是非妥协条件； 好处是确保输出符合特定品质标准和约束条件， 坏处是多轮迭代增加 latency 和成本， 设计 exit condition 本身也增加复杂度。 第二个是 coordinator router pattern， top-level coordinator 像聪明的 project manager， 分析用户需求后把大任务拆成子任务委派给专门 sub-agents， 例如规划完整体验时 coordinator 委派给 food/transport 序向 agent、 nearby places 并行 agent、 trip calls agent， sub-agents 各自执行再回传结果； 用 LLM agent 实作 sub-agents 就能动态选择； 好处是极度灵活能解决复杂问题， 坏处是因为多层 routing 增加 latency 和成本， 加上多层结构设计和除错更复杂。 第三个是 agent as tool pattern， 跟 coordinator 表面相似但关键差异在控制权和状态管理， coordinator 把任务委派后 sub-agent 拿走完整控制权自己解决， agent as tool 则是 primary agent 把 sub-agents 当无状态工具呼叫， sub-agent 执行一个函式回传结果， 主要 agent 保留完整控制权管理整体状态， 例如 coordinator 像 manager 把专案交给员工、 agent as tool 像工匠拿起特定工具做完一步再换下一步。 整支影片的核心讯息是， 选对 pattern 取决于需求特性， simple prototype 用 single agent， reliable structured workflow 用 sequential 或 parallel agent， 要符合特定条件用 loop， 要动态灵活 routing 解复杂问题用 coordinator 或 agent as tool， 每个 design 在 control、 flexibility、 cost、 complexity 之间都有 trade-off。
