Boris Cherny 在 Y Combinator Startup School 2026 的这场访谈，时机特殊——Anthropic 前一天才刚发布 Opus 5。这场对谈从三个层面谈 Claude Code 的设计哲学，以及当底层模型能力持续加速时，AI 产品该如何跟上。

首先，Opus 5 带来的根本改变是 long-running autonomous tasks。在 auto mode 下，模型可以连续跑几天、几周甚至几个月，不需要外部 scaffolding。对工程师来说，这代表 LangChain、LlamaIndex 风格的 agent scaffold 可能即将过时——Opus 5 已经内建 long-running agentic loop，不再需要 task planner 跟 state machine 这类外部框架。

第二个突破是 prompt injection。Boris 直接说 Opus 5「does not seem to be prompt injectable anymore」。这对 agent design 是结构性改变。过去 lethal trifecta——untrusted input 加上 code execution 加上 outgoing communication——让 prompt injection 成为 agent design 的核心约束。Opus 5 之后这个约束明显放松。对 Claude Code、Codex 这类 agent 工具来说，未来可以更信任 tool output 跟 file content。

第三个主题是 Claude Code 自己的演进。Boris 提到 Claude Code 砍掉了八成的 system prompt，从几千行缩到几百行。呼应「press delete on your AI product」的设计哲学——能删就删，每多一行 prompt 都是模型能力的锁链。背后逻辑是 Product overhang 概念：模型能力领先产品能利用的能力，差距越大越浪费。Claude Code 的工作就是不断 unhobbling 模型，把 Opus 5 的能力完整释放。

Boris 对 AI coding 工具开发者的具体建议是「给 AI 更难的问题」。不要给过度具体的指令，而是给高层次的任务描述、guardrails、exit criteria，然后让模型自己 cook。Boris 举 Bun 开源 runtime 的例子——Jared 从手动 fuzz 找 memory leak，到让 Opus 5 一次 prompt rewrite Zig 到 Rust，整整跑了十一天。

另外，Boris 提到 Anthropic 自己每天用 Claude 跑几千个 agents 做 codebase maintenance——清 dead code、删 useless tests、抽象统一。Claude Code 已经在自我维护，取代「dozens or hundreds of engineers」的工作量。对 CS 学生的建议是：coding skill 的边际价值在降低，business、design、user sense 的价值在提升。
