本課程由 DeepLearning.AI 與 JetBrains 共同製作，由 JetBrains 開發者倡導者 Paul Ehrlich 主講，Andrew Ng 在開場介紹時特別點出，specification-driven development（簡稱 SDD）是目前用輔助型 agent 建構嚴謹應用程式時的最佳工作流程，並強調「agent is the muscle, specification is the brain」這條核心精神。

課程一開始就揭示 SDD 的三大優點。第一，改動 spec 的小句子就能大規模改動程式碼，例如把「使用 SQLite 搭配 Prisma ORM」換成 MongoDB，往往會觸發數百行程式碼的異動；改變資料庫驅動、UI 框架、CSS 樣式皆然，寫 spec 的效率遠高於直接寫程式。第二，spec 能在不同 session 之間保留主要需求，因為 agent 本身是無狀態的，將最高品質的 context 在開工當下就交給 agent，是避免 context window overflow 與 context loss 的關鍵，也是防止 agent 在長對話中產生「cognitive debt」的核心手段。第三，spec 能提升意圖的準確度，先把問題、成功條件、限制、使用者路徑寫清楚，再請 agent 規劃，能大幅降低「憑直覺寫程式」的風險，並讓程式碼更貼近長期維護需求。

在流程上，SDD 強調要在專案層級建立一份「constitution」（章程），用 Markdown 把 mission、technology stack、roadmap 三件事寫清楚，並在每一輪 feature 開發中走 planning、implementation、verification 三階段，每個 feature 各自開 branch 隔離，藉此減少 context switching 與 AI fatigue。這套流程對 greenfield 與 brownfield 同樣適用：greenfield 從空白開始對話產出 charter；brownfield 則根據既有 readme、todo、commit 紀錄反推出 charter，再走相同的 feature cycle。Constitution 是活的文件，後續可透過 refactoring branch 獨立演進，並用來對齊所有 agent 之後寫出的程式碼風格。

課程也演示了把重複查詢包成 skill 的方法，讓 agent 自己呼叫 agent，例如自動更新 changelog、跑測試、做 lint 檢查；skill 可以放在 local 或 global，依團隊標準化程度決定。Spec Kit、Open Spec 等開源框架則提供 constitution、plan、tasks、proposal 等標準化模板，方便團隊快速導入並落實 Git branch 管理。課程最後介紹 ACP（Agent Client Protocol）與 ACP Registry，讓 IDE 能自動發現、安裝並切換不同 agent，整個 SDD 工作流程因此可以脫離特定 IDE 或特定模型存活。從 vibe coding 走向 SDD，本質就是讓 spec 成為專案的永久記憶，把工程紀律還給軟體開發。課程最後提醒，agent 與模型迭代速度極快，不應該把整個 workflow 綁死在單一工具或單一 IDE 上；透過 agents.md、skill、ACP 等開放標準，團隊可以在不同 agent 之間自由切換，卻仍然保留同一套 SDD 流程。這也是為什麼 spec 必須隨著 charter、feature、refactoring 持續更新，而不是寫一次就丟著。寫 spec 的當下確實需要花心力，但對照 agent 可能連續工作 20 到 30 分鐘、產出數小時的程式碼量，先投資 3 到 4 分鐘把 spec 寫清楚，永遠比事後補救來得划算。SDD 的精神，正是讓人類回到 senior architect 的位置，把設計、驗收、規格演進的責任扛起來，讓 agent 專心做 production-grade 的肌肉工作。
