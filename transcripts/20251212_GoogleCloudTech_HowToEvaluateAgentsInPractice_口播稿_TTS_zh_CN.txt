Google Cloud Tech 推出 AI agent 评估系列教学影片， 这是系列第二集也是完结篇， 介绍如何用 ADK 实际评估 agent。 影片用十分多钟说明三层测试金字塔， 以及 ADK 怎么落地这套框架。 第一部分介绍三层测试金字塔——Tier 1 是 component level unit test 测试最小建构块如 tool 选对没有、 参数格式对没有， 特性是 fast、 cheap、 automated， 适合 CI 早期抓 regression； Tier 2 是 trajectory level integration test 测试完整多步任务 end to end， 包括 agent 计划合不合理、 工具使用顺序对不对、 有没有在失败时调适、 有没有记得早期资讯、 是否达成目标； Tier 3 是 end to end human review 让人进 loop 检查整体体验包括 helpfulness/safety/common sense， 特性是 slow 和 expensive 但作为最终 quality gate。 三层互补形成完整的 testing strategy。 第二部分说明 ADK 怎么落地——用 book finder agent 范例展示， agent 用 Gemini 2. 5 Pro 当 brain 配三个工具包括 search local library、 find local bookstore、 order online， 评估时要测整个 book finding journey 也就是 trajectory； trajectory 涵盖 tool call 序列加参数、 中间步骤与推理、 最终回应； ADK 提供两个 built-in metric 包括 tool_trajectory_average_score 衡量实际 tool call 跟预期序列的吻合度（0 到 1 设 threshold）、 response_match_score 衡量最终答案跟预期答案的相似度（底层用 ROUGE 算 precision+recall， 0 到 1 设 threshold， 因为 agent 是 non-deterministic 要避免设 1）。 第三部分 demo 实际写 test：Tier 1 测 tool 选对跟参数对、 tier 2 用 ADK eval 测多步计划跟最终答案品质， 设 tool_trajectory_average_score=0. 8 跟 response_match_score=0. 5 平衡严格度跟自然语言变化。 整支影片的核心讯息是：用三层测试金字塔 + ADK built-in tools 搭配可以把评估从「这个 agent 感觉能用」升级到「这个 agent 确实可靠」， 这套方法把 agent evaluation 从理论变成可重复执行的自动化检查。
