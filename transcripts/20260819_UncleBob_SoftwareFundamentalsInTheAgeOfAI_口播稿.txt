Uncle Bob Martin 與 Matt Pocock 在一場 56 分鐘的直播訪談中，圍繞「AI 時代的軟體基礎」展開對話，核心論點是：過去三十年工程界覺得太貴而沒人執行的紀律，如今因為 AI agent 的速度成本，終於變得可行。紀律沒有死亡，只是換了執行者。

Uncle Bob 回顧自己的工程生涯：十二歲寫第一支程式，至今超過六十年。他坦承 2025 年 12 月才開始認真使用 agent，第一個 Grok agent 寫程式很快，卻不斷留下需要清理的技術債，讓他意識到 agent 雖然快速，卻反而讓自己變慢。然而正因 agent 速度夠快，過去理想化卻不可行的工具得以重出江湖。

2000 年代有兩項 Uncle Bob 認為優秀卻難以推廣的創新。其一是 CRAP score，結合測試覆蓋率與循環複雜度，原本是追蹤程式碼健康度的絕佳指標，但每次跑完要花數週修正。其二是突變測試，自動翻轉負號、小於、大於等運算符號，檢驗現有測試是否能抓出缺陷，速度慢到不可行。Agent 的出現改變了成本結構，兩項工具現在都能在合理時間內完成循環。

但 agent 並非萬能。Uncle Bob 引用 Dex Horby 的 smart zone 與 dumb zone 概念：context window 前段約十五萬 tokens 表現聰明，之後注意力便急劇稀釋，中段資訊幾乎被忽略。這意味著冗長的提示詞效果有限，確定性的程式碼檢查工具才是真正可信賴的紀律執行者。

解方之一是多 agent 專業化。把任務拆分給不同專長的 agent，包括規格制定者、實作者、審查者、硬化者，各自維持簡潔的 context。實作者只需寫出壞測試再讓它通過，審查者接手優化，工序分工模擬 TDD 循環。同時 Well-disciplined 模組與乾淨介面依然重要，agent 看到介面即可使用，無需閱讀整段實作，這正是 John Ousterhout《A Philosophy of Software Design》中 deep modules 概念的核心精神。

談到函式大小，Uncle Bob 提出務實的門檻調整：人類開發者維持 CRAP score 四以下，agent 容許六甚至八，底線仍是百分之百測試覆蓋率與循環複雜度限制。Agent 的短期記憶比人類準確，這是門檻得以放寬的唯一理由，但 TDD 紀律絕不妥協。

最震撼的轉變是修改成本已趨近於零。Uncle Bob 主張不必過度前置設計，直接反覆嘗試、檢查、調整，直到結果正確即可。規格因此變得短暫易逝，終點結果本身就是規格。他建議直接讓 agent 觀摩現有工具，自行建構客製化版本，而非下載他人成品。

在戰術與戰略程式設計的光譜上，agent 擅長戰術，拙於戰略。對新進工程師，Uncle Bob 給出具體路徑：先寫一年程式，再進入高度運用 agent 的公司被當作 agent 對待，受同樣紀律約束數月，從中學習戰略思維，最終成為能夠監督 agent 的人。經典老書如 DeMarco、Yourdon、《Pragmatic Programmer》仍是指南，因為這些戰略教訓早在七零、八零年代就已成形。

Uncle Bob 最後援引 Dijkstra：軟體是人類嘗試過最複雜的事物，基礎紀律正是組織複雜性的方式，agent 與人類都需要這套紀律。抽象層次從機械碼、組合語言、編譯器一路提升到模型，每一階段都有人宣稱會摧毀一切，最終證明都是過慮。紀律沒有死亡，只是換了執行者，而執行者變得比以往更快。
