Google Cloud Tech 推出 AI agent 評估系列教學影片，這是系列第二集也是完結篇，介紹如何用 ADK 實際評估 agent。影片用十分多鐘說明三層測試金字塔，以及 ADK 怎麼落地這套框架。第一部分介紹三層測試金字塔——Tier 1 是 component level unit test 測試最小建構塊如 tool 選對沒有、參數格式對沒有，特性是 fast、cheap、automated，適合 CI 早期抓 regression；Tier 2 是 trajectory level integration test 測試完整多步任務 end to end，包括 agent 計畫合不合理、工具使用順序對不對、有沒有在失敗時調適、有沒有記得早期資訊、是否達成目標；Tier 3 是 end to end human review 讓人進 loop 檢查整體體驗包括 helpfulness/safety/common sense，特性是 slow 和 expensive 但作為最終 quality gate。三層互補形成完整的 testing strategy。第二部分說明 ADK 怎麼落地——用 book finder agent 範例展示，agent 用 Gemini 2.5 Pro 當 brain 配三個工具包括 search local library、find local bookstore、order online，評估時要測整個 book finding journey 也就是 trajectory；trajectory 涵蓋 tool call 序列加參數、中間步驟與推理、最終回應；ADK 提供兩個 built-in metric 包括 tool_trajectory_average_score 衡量實際 tool call 跟預期序列的吻合度（0 到 1 設 threshold）、response_match_score 衡量最終答案跟預期答案的相似度（底層用 ROUGE 算 precision+recall，0 到 1 設 threshold，因為 agent 是 non-deterministic 要避免設 1）。第三部分 demo 實際寫 test：Tier 1 測 tool 選對跟參數對、tier 2 用 ADK eval 測多步計畫跟最終答案品質，設 tool_trajectory_average_score=0.8 跟 response_match_score=0.5 平衡嚴格度跟自然語言變化。整支影片的核心訊息是：用三層測試金字塔 + ADK built-in tools 搭配可以把評估從「這個 agent 感覺能用」升級到「這個 agent 確實可靠」，這套方法把 agent evaluation 從理論變成可重複執行的自動化檢查。
