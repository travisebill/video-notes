Uncle Bob Martin 与 Matt Pocock 在一场 56 分钟的直播访谈中， 围绕「AI 时代的软体基础」展开对话， 核心论点是：过去三十年工程界觉得太贵而没人执行的纪律， 如今因为 AI agent 的速度成本， 终于变得可行。 纪律没有死亡， 只是换了执行者。

Uncle Bob 回顾自己的工程生涯：十二岁写第一支程式， 至今超过六十年。 他坦承 2025 年 12 月才开始认真使用 agent， 第一个 Grok agent 写程式很快， 却不断留下需要清理的技术债， 让他意识到 agent 虽然快速， 却反而让自己变慢。 然而正因 agent 速度够快， 过去理想化却不可行的工具得以重出江湖。

2000 年代有两项 Uncle Bob 认为优秀却难以推广的创新。 其一是 CRAP score， 结合测试覆盖率与循环复杂度， 原本是追踪程式码健康度的绝佳指标， 但每次跑完要花数周修正。 其二是突变测试， 自动翻转负号、 小于、 大于等运算符号， 检验现有测试是否能抓出缺陷， 速度慢到不可行。 Agent 的出现改变了成本结构， 两项工具现在都能在合理时间内完成循环。

但 agent 并非万能。 Uncle Bob 引用 Dex Horby 的 smart zone 与 dumb zone 概念：context window 前段约十五万 tokens 表现聪明， 之后注意力便急剧稀释， 中段资讯几乎被忽略。 这意味著冗长的提示词效果有限， 确定性的程式码检查工具才是真正可信赖的纪律执行者。

解方之一是多 agent 专业化。 把任务拆分给不同专长的 agent， 包括规格制定者、 实作者、 审查者、 硬化者， 各自维持简洁的 context。 实作者只需写出坏测试再让它通过， 审查者接手优化， 工序分工模拟 TDD 循环。 同时 Well-disciplined 模组与干净介面依然重要， agent 看到介面即可使用， 无需阅读整段实作， 这正是 John Ousterhout《A Philosophy of Software Design》中 deep modules 概念的核心精神。

谈到函式大小， Uncle Bob 提出务实的门槛调整：人类开发者维持 CRAP score 四以下， agent 容许六甚至八， 底线仍是百分之百测试覆盖率与循环复杂度限制。 Agent 的短期记忆比人类准确， 这是门槛得以放宽的唯一理由， 但 TDD 纪律绝不妥协。

最震撼的转变是修改成本已趋近于零。 Uncle Bob 主张不必过度前置设计， 直接反复尝试、 检查、 调整， 直到结果正确即可。 规格因此变得短暂易逝， 终点结果本身就是规格。 他建议直接让 agent 观摩现有工具， 自行建构客制化版本， 而非下载他人成品。

在战术与战略程式设计的光谱上， agent 擅长战术， 拙于战略。 对新进工程师， Uncle Bob 给出具体路径：先写一年程式， 再进入高度运用 agent 的公司被当作 agent 对待， 受同样纪律约束数月， 从中学习战略思维， 最终成为能够监督 agent 的人。 经典老书如 DeMarco、 Yourdon、 《Pragmatic Programmer》仍是指南， 因为这些战略教训早在七零、 八零年代就已成形。

Uncle Bob 最后援引 Dijkstra：软体是人类尝试过最复杂的事物， 基础纪律正是组织复杂性的方式， agent 与人类都需要这套纪律。 抽象层次从机械码、 组合语言、 编译器一路提升到模型， 每一阶段都有人宣称会摧毁一切， 最终证明都是过虑。 纪律没有死亡， 只是换了执行者， 而执行者变得比以往更快。
