本集 AI Hero 技能庫由 Matt Pocock 主講，聚焦於一個他在 LLM 編碼時代長期反對、卻日益盛行的反模式 — spec-driven development。Matt 在影片開頭直接點明核心張力：需要製定一個計劃，對吧？計劃模式，規範驅動開發。需要投入所有精力來製定這個極其詳細的規範⋯⋯而在這種衝動之下，他們忘了自己其實可以寫程式。這項觀察呼應敏捷開發時代的原型設計傳統，但 Matt 更進一步指出，隨著 LLM 編碼成本大幅下降，「生產原型、快速生產一次性尖頭產品從未如此便宜，也從未如此有效。」

第一個張力是設計討論的保真度分級。Matt 將設計問題分為三層：簡單的基本框架問題（例如 modal 應有取消/確認按鈕）透過純討論即可解決；中等保真度的問題（例如模態框開啟時如何展示資料）需要更高層級的探討；而真正複雜的事物外觀 + 在特定情境的行為方式，則只能在半工作程式碼中測試。從經濟學角度，這呼應了 Ryan Singer 在《Shape Up》中提出的「拉力 vs 推力」框架 — 當討論的精確度降低，答案的實用性也降低，但 token 成本也降低；保真度越高則反之。

第二個張力是 `/prototype` 與 `/wayfinder` 的工具整合。Matt 展示 Wayfinder 的票種設計：預設是 grill（與 agent 對話釐清範圍），但當「它應該看起來怎麼樣」「它應該如何表現」成為關鍵問題時，切換到 prototype 票 — 製作廉價、粗糙、具體的工件來回答問題。從工具哲學角度，這體現了「context-dependent fidelity」原則：同一個 skill 系統內，根據問題性質動態切換討論模式，是 LLM 時代設計工具的核心演化方向。

第三個張力是實戰 demo 揭露的反直覺發現。Matt 為自己的 TLDraw 圖表繪製 app 加搜尋欄，因資料模型複雜（圖表 + 時間快照），啟動 prototype 生成 A/B/C 三個版本。每次迭代使用約 10 萬 token，但產出的是「保留所有設計決策 + 給反饋」的高保真資產，而非隨意丟棄的草稿。最終 D 版本合併了 A 的搜尋框 + C 的佈局，並與即時路由整合 — 讓 prototype 成為「程式碼實際運作方式的真實寫照」，而非紙上談兵。

結尾轉向 prototype 的非 UI 應用。Matt 反對「原型只跟前端有關」的刻板印象，展示一個處理狀態機的小型互動終端應用 — 純邏輯 prototype。從軟體工程史角度，這呼應了 1970 年代 Smalltalk 環境中「先建構可運作的最小實例，再擴展為完整系統」的探索式編程傳統。Matt 最後引用 Ryan Singer 的《Shape Up》作為思想根源：「從討論和規範到可用於生產的程式碼，這之間的差距非常大。然而，如果你有一個可用的原型，將其轉化為量產產品就相當簡單了。」

這支影片最鮮明的口號是：原型不是浪費時間，而是用最便宜的程式碼，回答最難的設計問題 — 在 LLM 時代，當程式碼成本趨近於零，設計討論的保真度天花板，便決定了最終產品的品質上限。
