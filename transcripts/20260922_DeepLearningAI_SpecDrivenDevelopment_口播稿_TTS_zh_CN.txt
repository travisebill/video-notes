本课程由 DeepLearning.AI 与 JetBrains 共同制作， 由 JetBrains 开发者倡导者 Paul Ehrlich 主讲， Andrew Ng 在开场介绍时特别点出， specification-driven development（简称 SDD）是目前用辅助型 agent 建构严谨应用程式时的最佳工作流程， 并强调「agent is the muscle, specification is the brain」 这条核心精神。 

课程一开始就揭示 SDD 的三大优点。 第一， 改动 spec 的小句子就能大规模改动程式码， 例如把「使用 SQLite 搭配 Prisma ORM」 换成 MongoDB， 往往会触发数百行程式码的异动； 改变资料库驱动、 UI 框架、 CSS 样式皆然， 写 spec 的效率远高于直接写程式。 第二， spec 能在不同 session 之间保留主要需求， 因为 agent 本身是无状态的， 将最高品质的 context 在开工当下就交给 agent， 是避免 context window overflow 与 context loss 的关键， 也是防止 agent 在长对话中产生「cognitive debt」 的核心手段。 第三， spec 能提升意图的准确度， 先把问题、 成功条件、 限制、 使用者路径写清楚， 再请 agent 规划， 能大幅降低「凭直觉写程式」 的风险， 并让程式码更贴近长期维护需求。 

在流程上， SDD 强调要在专案层级建立一份「constitution」 （章程）， 用 Markdown 把 mission、 technology stack、 roadmap 三件事写清楚， 并在每一轮 feature 开发中走 planning、 implementation、 verification 三阶段， 每个 feature 各自开 branch 隔离， 借此减少 context switching 与 AI fatigue。 这套流程对 greenfield 与 brownfield 同样适用： greenfield 从空白开始对话产出 charter； brownfield 则根据既有 readme、 todo、 commit 纪录反推出 charter， 再走相同的 feature cycle。 Constitution 是活的文件， 后续可透过 refactoring branch 独立演进， 并用来对齐所有 agent 之后写出的程式码风格。 

课程也演示了把重复查询包成 skill 的方法， 让 agent 自己呼叫 agent， 例如自动更新 changelog、 跑测试、 做 lint 检查； skill 可以放在 local 或 global， 依团队标准化程度决定。 Spec Kit、 Open Spec 等开源框架则提供 constitution、 plan、 tasks、 proposal 等标准化模板， 方便团队快速导入并落实 Git branch 管理。 课程最后介绍 ACP（Agent Client Protocol）与 ACP Registry， 让 IDE 能自动发现、 安装并切换不同 agent， 整个 SDD 工作流程因此可以脱离特定 IDE 或特定模型存活。 从 vibe coding 走向 SDD， 本质就是让 spec 成为专案的永久记忆， 把工程纪律还给软体开发。 课程最后提醒， agent 与模型迭代速度极快， 不应该把整个 workflow 绑死在单一工具或单一 IDE 上； 透过 agents.md、 skill、 ACP 等开放标准， 团队可以在不同 agent 之间自由切换， 却仍然保留同一套 SDD 流程。 这也是为什么 spec 必须随著 charter、 feature、 refactoring 持续更新， 而不是写一次就丢著。 写 spec 的当下确实需要花心力， 但对照 agent 可能连续工作 20 到 30 分钟、 产出数小时的程式码量， 先投资 3 到 4 分钟把 spec 写清楚， 永远比事后补救来得划算。 SDD 的精神， 正是让人类回到 senior architect 的位置， 把设计、 验收、 规格演进的责任扛起来， 让 agent 专心做 production-grade 的肌肉工作。
